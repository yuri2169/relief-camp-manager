# Relief Camp Manager — web interface

A companion web view of the same Morigaon dataset the console program uses,
built for the Seva First Innovation Challenge entry so judges can see the
project without a terminal.

**This is not part of the CS 203 submission.** The graded program is the C++17
console application in the repository root: standard library only, no GUI, no
networking, offline. This folder is a separate presentation layer with its own
toolchain, and nothing in it is compiled, linked or tested by the `Makefile`.
The two share no code; they share a dataset.

## Run it

```bash
npm install
npm run dev
```

Then open http://localhost:3000. The app screens are under
http://localhost:3000/app.

## Routes

| Route | What it shows |
|---|---|
| `/` | Landing page: headline, the numbers, the problem, how it works, the demo |
| `/app` | Overview: items below three days, a tile per camp, the transfer panel |
| `/app/camps` | All three camps with occupancy, days of supply and status |
| `/app/camps/[id]` | One camp: days of supply, facts, stock table, supply chart, health log |
| `/app/register` | Register a family, with the ration card computed as you type |
| `/app/settings` | Settings form |
| `/app/states` | The empty, loading and error states in one place |

## Where the figures come from

Nothing here is invented. The dataset and the arithmetic mirror the console
program, so the two agree to the decimal:

- `content/demo-data.ts` holds the three camps, their stock and their health
  rows, taken from the committed seed files in `../data/`. Quantity divided by
  daily demand reproduces the days of supply the console app prints.
- `lib/supply.ts` computes days of supply and the inter-camp transfers by the
  same rule as `TransferAdvisor` in `../src/TransferAdvisor.cpp`, including the
  guard that stops one donor's spare stock being pledged to two receivers in a
  single pass. It is why the panel proposes 22.2 kg of rice from Mayong to
  Laharighat, as `../docs/VERIFICATION.md` records.
- `lib/ration.ts` carries the ration norms from `../src/RationNorms.cpp` and the
  vulnerability scores from each `Person` subclass. Registering one infant, one
  elderly member and one adult gives a score of 85, the same figure the console
  app prints on its ration card.

Ticking the camp duty on a working-age adult turns them into a resident
volunteer: one `Person` reached through two inheritance paths, with the
ambiguity resolved in favour of `Adult`. The card explains it on screen.

## Nothing is written

The web interface is read-only over a fixed snapshot. It does not touch the
CSV files, and the demo date is pinned to 14 July 2026 so the figures never
drift. The buttons that look like they commit something say so when pressed.

## The design system

`CLAUDE.md` holds the rules this interface is built to: one accent colour, one
typeface, square corners, no shadows, every string in `content/site.ts` rather
than in components. Read it before changing anything here. `AGENTS.md` is
generated by `next dev` and is not worth reading.
